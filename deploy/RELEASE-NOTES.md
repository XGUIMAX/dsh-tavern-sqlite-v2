# 0.4.8 Tavern 2.6多插图与DB资源便携

## 适配酒馆版本

本版适配上游 [DSH Tavern main `038cc63`](https://github.com/flizzywine/dsh-tavern/commit/038cc63fc438c01e2b4b13ff24e3438c974cd27f)：Tavern **2.6.0**，完整提交 `038cc63fc438c01e2b4b13ff24e3438c974cd27f`，作者代码版本 `39602e9f70549e979446a3752fced786a3b5bab9`，DSH SDK **0.1.5-rc.2**。

**其他未适配的酒馆版本使用过程中可能出现运行错误。安装接入检查通过不代表运行期功能兼容；请更新到本 Release 标注的适配酒馆版本，或自行适配本插件后使用。**

酒馆升级覆盖插件区块后，请停止对应酒馆并运行一次安装维护以重接。接口变化仍需对应适配，不以安装成功推断所有运行功能兼容。

## 更新内容

- 适配Tavern 2.6每轮最多6个场景插图slot：DB存档按`turn + slot`捕获、校验和重绑场景记录；旧代无slot能力时对含slot的包响亮拒绝，不猜测映射。
- 造型参考`references.json`随DB存档迁移：source/activation key逐槽换新，图片附件重存并取得新attachmentId，记录ID与撤销列表同步重写，失败写入纳入既有资源回滚。
- 支持作者正常的取消绑定记录（`enabled:false + image:null`）；闭包外或已失效的参考记录不进入新包。
- DB存档携带当前可见版本的插件数据、媒体与图片/通用文件附件、游戏级数据和本局设置；导入生成新chat/session/textVersion/媒体ID/附件引用。
- 目标部分恢复或发布失败时补偿新目标插件副数据；已有副数据拒绝覆盖，共享缓存不误删。
- 停用新增发送前软墓碑清理；失败输入先经统一物理清理，不在正在prepare的Agent内自动回退自身。不同轮遗留模板输入先撤销变量，再捕获新业务回退基准。
- 操作前像历史随DB快照携带并重绑结构身份；旧无此表存档保持兼容。历史账本恢复与独立压缩警告视图修复一并纳入。

保留SQLite唯一权威、物理纯尾、事务/CAS、旧写隔离、同连接同步、原档只读及用户手动双新ID分叉。不会自动迁移、清理或删除既有存档。DB包仍不携带生图运行/审计字段，不续接源档在途生图任务。自动化证据不替代全部页面与真实玩法验收。
